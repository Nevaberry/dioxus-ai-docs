# Variants and States

## Boolean data attributes

Target a present boolean data attribute without arbitrary-variant brackets (`4.0.0`).

```html
<div data-current class="opacity-75 data-current:opacity-100"></div>
```

## Negated states and conditions

The `not-*` variant negates ordinary states, media conditions, and `@supports` conditions.

```html
<div class="not-hover:opacity-75"></div>
<div class="not-supports-hanging-punctuation:px-4"></div>
```

Choose the positive or negated form that keeps the default style easiest to understand.

## Implicit ancestor state

The `in-*` variant reacts to a matching ancestor like `group-*`, but does not require a `group` class on that ancestor.

```html
<div tabindex="0">
  <span class="opacity-50 in-focus:opacity-100">Visible on ancestor focus</span>
</div>
```

Use `group-*` when a named or explicit group relationship is useful; use `in-*` for an implicit matching ancestor.

## Open disclosures and popovers

The `open` variant also targets `:popover-open`, so the same state variant can style an open disclosure or an open popover directly.

```html
<div popover class="opacity-0 open:opacity-100">Popover content</div>
```

Negation, implicit ancestors, and popover-open support in the preceding sections are recorded in `4.0.0`.

## Pointing-device variants

Use `pointer-fine:` and `pointer-coarse:` to test the primary pointing device. Use `any-pointer-fine:` and `any-pointer-coarse:` when any connected device should qualify, such as a touchscreen attached to a mouse-driven laptop (`4.1.0`).

```html
<button class="p-2 pointer-coarse:p-4">Select</button>
```

The primary-pointer variants are usually appropriate for the main interaction design; the `any-pointer-*` forms are for capabilities offered by any available input.

## Details content

`details-content:` styles the content container generated by a `<details>` element, rather than merely selecting its child elements (`4.1.0`).

```html
<details class="details-content:mt-3">
  <summary>Question</summary>
  <div>Answer</div>
</details>
```

## Inverted colors

`inverted-colors:` matches an operating-system inverted-color scheme. Use it to adjust effects that invert poorly, such as removing a shadow (`4.1.0`).

```html
<div class="shadow-xl inverted-colors:shadow-none">...</div>
```

## JavaScript-disabled styles

`noscript:` applies CSS when JavaScript is disabled without requiring a `<noscript>` wrapper (`4.1.0`).

```html
<div class="hidden noscript:block">Please enable JavaScript.</div>
```

## Interaction-aware validation

`user-valid:` and `user-invalid:` style controls only after user interaction. Unlike immediate `:valid` or `:invalid` styling, they avoid showing an initial error on an untouched required field (`4.1.0`).

```html
<input required class="border user-valid:border-green-500 user-invalid:border-red-500" />
```

## Stacked and alternative CSS variants

Inside authored CSS, join variants with a colon to stack their conditions. Separate variants with commas to apply one declaration block to alternatives. This composition syntax is recorded in `4.3.0`.

```css
.button {
  @variant hover:focus {
    background: var(--color-sky-600);
  }

  @variant active, disabled {
    opacity: 50%;
  }
}
```

`hover:focus` requires both conditions. `active, disabled` emits the block for either condition.
