# Flutter tooling, builds, assets, and plug-ins

## Widget Preview

- In 3.32.0, top-level `@Preview()` builders replaced the removed interim
  `WidgetPreview` wrapper and launched an experimental, web-default preview
  scaffold.
- 3.35.0 replaced separate height/width with `size` and added `theme`, `brightness`,
  and localization.
- `3.38-guide` added VS Code and IntelliJ/Android Studio integration, initially
  filtering to the selected source file. `Preview` became subclassable,
  `MultiPreview` added variants, and `group` organized related previews. Private
  constants are accepted, but function-valued wrappers/themes need public,
  statically accessible names.
- The 3.38.0 command supports `--web-server` and `--machine`; move `--dtd-url` from
  the global command to `widget-preview start`.
- `3.41-guide` embeds Flutter Inspector. Add the project package directory in
  Inspector settings if widgets are missing. Transitive `dart:ffi`/`dart:io`
  imports may compile, but invoked platform APIs still fail; use web-compatible
  callable paths or conditional imports.
- `3.44-guide` filters by group, name, script URI, or package URI. 3.44.0 custom
  annotations accept collection and record values.

## Inspector, diagnostics, and profiling

- The redesigned DevTools Inspector is on by default; on-device selection remains
  active across selections until exited. Logging filters by severity and shows
  severity, category, zone, and isolate (`3.29.0`).
- `debugPaintTextLayoutBoxes = true` paints text layout boxes in debug builds
  (3.38.0).
- Use `flutter run --profile-microtasks` for `dart:async` microtask profiling
  (3.35.0), `flutter run --profile-startup` for startup profiling (3.38.0), and
  `dart info record-performance` for analysis-server traces (dart-3.12.0).
- Runtime diagnostics can read Flutter framework version information and
  `PlatformDispatcher.instance.engineId`, important in multi-engine processes
  (3.32.0).

## MCP and editor tooling

- The Dart and Flutter MCP server became stable in `3.35-guide`, providing widget
  tree, dependency, and analyzer operations. It added `read_package_uris` in
  dart-3.11.0.
- By `3.44-guide`, compatible coding tools can discover running apps and trigger
  hot reload after edits.
- Flutter Property Editor support in VS Code and JetBrains IDEs edits widget
  properties and shows docs (`3.32-guide`). Flutter IntelliJ M87 extends support to
  CLion, GoLand, and PyCharm; SDKs older than 3.13 were deprecated, with pre-3.16
  deprecation planned (`3.35-guide`).

## Assets and generated files

- `flutter: generate: true` remains valid only for non-synthetic output. Import
  generated localization files from their real output; the synthetic
  `package:flutter_gen` package is removed (3.32.0).
- Do not depend on SkSL data bundles or the removed iOS SkSL build target (3.32.0).
- `.flutter-plugins` is removed; consume `.flutter-plugins-dependencies` (3.35.0).
- `AssetManifest.json` is no longer generated by default (`3.38-guide`).
- `pubspec.yaml` asset entries can limit bundling with `platforms`, for example
  `[web]` or `[windows, linux, macos]` (`3.41-guide`).
- Listing one shader both as a shader and ordinary asset is a build error (3.41.0).
- Shader assets support flavors and asset transformers (3.44.0).

## Build hooks and native/data assets

- Native assets reached preview in 3.35.0; hooks can receive workspace-defined
  values and `flutter test integration_test` builds native assets from development
  dependencies.
- Build hooks and code assets are stable in 3.38.0, and tooling supports package-
  supplied data assets.
- Put a hook in `hooks/build.dart`; hooks run for run/build/test in dependency order
  with a restricted environment and shared output directory
  (`dart-3.11-tooling-guide`). Give each native code asset a
  `package:<package-name>/<asset-name>` ID matching its `@Native` lookup.

## Plug-in metadata and templates

- For a platform implementation with no native class, omit `pluginClass`; remove
  `pluginClass: none` (`3.35-guide`). Likewise omit `dartPluginClass` instead of
  setting `dartPluginClass: 'none'` (3.38.0).
- New plug-ins use Gradle Kotlin DSL by default (`3.41-guide`).
- Objective-C plug-in generation is deprecated in favor of Swift (3.38.0). The
  `plugin_ffi` template is deprecated; use the standard plug-in template with FFI
  support (`3.44-guide`).
- Apple plug-ins need SwiftPM support under the new default; AGP 9 plug-ins must
  remove separately applied Kotlin and declare a minimum Flutter SDK of 3.44
  (`3.44-guide`).

## Flutter GPU and shader tooling

- Experimental Flutter GPU resource-creation failures throw; catch exceptions
  instead of checking the former failure return (3.32.0).
- Enable the experimental API with `--enable-flutter-gpu`, or
  `FLTEnableFlutterGPU` in a macOS embedder (3.35.0).
- Flutter tooling supports named shader uniforms, sampler filter quality, shader
  flavors, and shader asset transformers; verify backend support before use.

## CLI contract changes

- `flutter assemble` accepts `--dart-define`/`-D`; `--define`/`-d` are deprecated.
  Removed `--disable-dds` and `--no-disable-dds` leave `--no-dds` as the opt-out.
  Removed `--fast-start` must not appear in scripts (3.38.0).
- Linux and Windows builds accept `--config-only`; web builds accept
  `--static-assets-url` (3.38.0).
- `flutter build` without a target exits 1. `flutter assemble` permits empty Dart
  defines. Chrome launches do not automatically pass `--no-sandbox` (3.41.0).
- `flutter test --ignore-timeouts` suppresses test timeouts (3.32.0), while
  `flutter test --no-uninstall integration_test` preserves the target installation
  (3.44.0).
- `flutter create` now writes `pubspec.lock` for a newly resolved project (3.44.0).

## Package migrations and support

- `firebase_ai` replaces `firebase_vertexai` for new Firebase AI Logic work and
  supports both Gemini API providers plus Imagen; existing clients continue to run
  but should migrate (`3.32-guide`).
- Flutter support was scheduled to end April 30, 2025 for `ios_platform_images`,
  `css_colors`, `palette_generator`, `flutter_image`,
  `flutter_adaptive_scaffold`, and `flutter_markdown`; select maintained forks or
  alternatives (3.29.0).

## Release channels and artifact provenance

- A branch cutoff is the date by which work must land on Dart `main` or Flutter
  `master` to be guaranteed for the next stable. The published 2026 windows were
  3.41 in February (January 6 cutoff), 3.44 in May (April 7), 3.47 in August
  (July 7), and 3.50 in November (October 6) (`release-and-news-catalogs`).
- Roughly every third beta is promoted to stable; beta usually ships on the first
  Wednesday monthly and fixes commonly take about two weeks from main. The main
  channel has no bundles and must be cloned from the repository.
- Flutter archives identify architecture, Git ref, release date, bundled Dart, and
  JSON provenance. Downloads include SLSA provenance.
- Flutter 3.47.0 stable bundles Dart 3.13.0. The `3.47.0` Linux artifact is
  `stable/linux/flutter_linux_3.47.0-stable.tar.xz`, commit
  `4cf24164269a5ebf0c16a028a00727d0e77bbb05`, SHA-256
  `26cd99d3d94b1367e6b50535a18aeef0282c10a535bbe3ec493534dcdab75296`,
  released August 12, 2026.
