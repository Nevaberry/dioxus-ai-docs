# Components, Reactivity, Events, and Hooks

Use this reference for component signatures, props, signals, stores, contexts,
tasks, resources, suspense, hook lifecycle, event handling, and error
propagation.

## Components and props

### Scope-free components and result elements

Since 0.5.0, components take props directly rather than a `cx: Scope`; their
`Element` and runtime helpers no longer carry the old bump lifetime. A signal
handle is `Copy` even if its value is not, while `use_signal_sync` creates a
`Send + Sync` handle for cross-thread use.

```rust
fn Counter() -> Element {
    let mut count = use_signal(|| 0);
    spawn(async move { println!("{}", count()) });
    rsx! { button { onclick: move |_| count += 1, "{count}" } }
}
```

Since 0.6.0, `Element` is a `Result`, `RenderError` accepts ordinary errors, and
components and async handlers can propagate errors with `?`. Render deliberate
absence as `rsx! {}` rather than `VNode::None`. The older `.throw()` adapter
still explains 0.5-era code: it converted a debuggable error into render error
state so an ancestor `ErrorBoundary` could handle it.

### Reactive props and prop decay

Declare a readable reactive prop as `ReadSignal<T>`. RSX decays a signal, memo,
or store lens into it and can lift a plain value, which lets a child remain
generic over its caller's state primitive.

```rust
#[component]
fn Validator(is_valid: ReadSignal<bool>) -> Element {
    rsx! { if !is_valid() { "Invalid" } }
}
```

The older workaround for a non-`Clone` prop was `ReadOnlySignal<T>` in 0.5.0;
that type is deprecated as of 0.7.0 in favor of current readable interfaces.
Generated generic props stopped adding unnecessary `Clone` bounds in 0.7.6.

An `Option<T>` prop is optional at the call site unless marked
`#[props(!optional)]`. `#[props(into)]` accepts `Into` conversions, while
`String` already accepts formatted-string syntax. Constructed props can be
spread with `..props`; explicit fields override spread fields.

```rust
#[component]
fn Label(
    #[props(!optional)] tooltip: Option<String>,
    #[props(into)] text: String,
) -> Element {
    rsx! { span { title: tooltip, "{text}" } }
}
```

### Preview component-prop contract

> **Prerelease (`0.8.0-alpha.0`):** This guidance may change before stable release.

Props generated by `#[component]` are non-exhaustive. Downstream crates must
not exhaustively match them or directly construct them on the assumption that
the field set can never grow.

## Signal subscription and scheduling

### What creates a subscription

A component subscribes when it reads a signal during rendering, not when the
only read occurs in an event handler or unrelated async task. `use_memo`,
`use_future`, `use_resource`, and other reactive scopes track their own reads.
Use `peek()` to read without subscribing and `use_reactive` to wrap an explicit
tuple of otherwise untracked dependencies.

A memo recomputes when an input changes but publishes only when `PartialEq`
says its output changed. Effects run after the UI paint, so use them to update
external state only for a render that survived.

### Runtime steps and fresh values

Writes in one runtime step are batched and dependent work is deduplicated. An
`.await` ends the step and allows pending UI to paint. Reading a dependent memo
immediately after a write recomputes it synchronously rather than returning a
stale value.

### Ownership and disposal

Hook-created signals and `Signal::new()` values belong to the current component
and are disposed on unmount; reading a copied handle afterward panics.
Repeatedly inserting new signals into a collection retains their contents
until the owner unmounts unless they are manually disposed. Prefer stores and
reactive collection mapping for dynamic children.

## Global and contextual state

`GlobalSignal` replaced atom-style global state in 0.5.0. Ordinary signals can
be shared with `use_context_provider` and `use_context`. `consume_context` may
also run in handlers and polled futures because those callbacks carry the
current runtime; dynamically calling `provide_context` replaces this
component's entry but is not reactive.

A global static is scoped to one Dioxus app instance, so SSR tenants and
desktop windows do not share it. `Memo::global` provides derived app-local
global state. During the 0.6.0 migration, `GlobalSignal` and `GlobalMemo` became
aliases over `Global`, and `.resolve()` replaced the old `.signal()` and
`.memo()` accessors.

`EventHandler<T>` and `Callback<Input, Output>` carry the runtime. Prefer them
over a plain closure when a filesystem watcher or another external API later
invokes code that needs runtime services.

## Stores and lenses

`#[derive(Store)]` creates nested field projections. Reactive collections
invalidate affected items rather than every collection consumer. Generated
lenses have an intentionally unnamed type, so helpers accept bounds:

```rust
fn clear_title(state: Store<HeaderState, impl Writable<Target = HeaderState>>) {
    state.title().take();
}
```

At a component boundary, writable and read-only lenses are boxed and decay to
`ReadSignal` or `ReadStore` props. For `Option` and `Result`, `.transpose()`
returns a wrapped inner lens and preserves precise reactivity; `.as_ref()`
performs a read and cannot be lensed farther. An impl marked `#[store]` becomes
an extension trait for all lenses, adding `Readable` for `&self` methods and
`Writable` for `&mut self`.

Iteration over `Signal<Vec<T>>` cannot lend references from its read guard to
children. Clone cheap values, pass the signal plus an index, or use `Store`;
store iteration yields per-item lenses suitable for child props.

Since 0.7.2, synchronized state uses `SyncStore` and `use_store_sync`. Since
0.7.4, `WritableResultExt` adds operations specialized for writable `Result`
values.

### Preview store visibility and readable conversion

> **Prerelease (`0.8.0-alpha.0`):** This guidance may change before stable release.

Store derives preserve the source fields' and methods' visibility through
visibility witness types. A generated accessor cannot bypass Rust visibility.

> **Prerelease (`0.8.0-alpha.1`):** This guidance may change before stable release.

Converting a `MappedMutSignal` to `ReadStore` requires `Lens: Readable`; generic
helpers performing that conversion must declare the bound.

## Tasks, actions, resources, and suspense

### Choose task ownership deliberately

`spawn` attaches a single-threaded `!Send` future to the current component and
cancels it on unmount. Keep its `Task` to call `.cancel()`. `spawn_forever`
attaches work to the root and must not capture signals owned by a shorter-lived
component. Move CPU-heavy work to a native thread or Web Worker.

`use_action` stores `None` or the latest `Result`; `.call(input)` starts work,
and a later call cancels and replaces pending work. This prevents the stale
completion race of repeatedly spawned async event handlers. `Action` implements
`PartialEq` since 0.7.6.

```rust
let mut double = use_action(|value: i32| async move {
    anyhow::Ok(value * 2)
});
double.call(21);
```

### Resources and loaders

`use_resource` tracks reads made inside its future, cancels and restarts on a
dependency change, and notifies readers after every run even if the value
compares equal. Its output must be cloneable; wrap `anyhow::Error` in
`CapturedError`, or use `dioxus::Ok(value)` to construct
`Result<T, CapturedError>`.

For a future returning `Result<T, E>`, `use_loader` returns
`Result<Loader<T>, Loading>` and lets `?` route pending and failure states to
suspense and error boundaries. Start independent loaders before the first `?`
to avoid a waterfall.

### Suspense and server hydration

Since 0.6.0, a `SuspenseBoundary` renders a fallback while a descendant applies
`.suspend()?` to a pending resource; Fullstack can stream each completed
boundary. A child can use `with_loading_placeholder` to propose its own loading
view.

Fullstack suspense should use `use_server_future`, which serializes the server
result for hydration and suspends automatically. Only its outer closure is
reactive, so read dependencies there rather than only inside the returned
future.

## Hooks and cleanup

Hooks cannot appear in conditionals, loops, or closures. Dioxus does permit an
early return between hooks so suspense and error `?` propagation works, though
putting all hooks before a return keeps the effective hook list simpler.

`use_hook` initializes stored state once and retains it until component
destruction. Use `use_on_destroy` or `use_drop` for cleanup; `use_drop` has been
in the prelude since 0.7.2. Low-level custom hooks can call
`dioxus::core::needs_update()` to queue their component after non-signal state
changes. `use_coroutine` accepts `FnMut` since 0.6.0, so its closure can restart
without a component rerender.

## Events and error boundaries

### Native events

Portable events expose renderer-specific payloads. Older 0.5.0 web code used
`web_event()`; current code can use `event.downcast::<T>()`. Desktop asset
handlers can stream bytes into the webview, and file drops use normal events.
Native file-drop handlers return full paths since 0.7.3; browser
`WebFileData::file_path` preserves `webkitRelativePath` since 0.7.2.

The normal event set gained `auxclick` and `scrollend` in 0.7.3. References to
supported attribute values implement `IntoAttributeValue` and the global
`inert` attribute is typed since 0.7.6. A panic in a Web event handler no longer
permanently disables later interaction as of 0.7.6.

### Resize, visibility, mount, and cancellation

`onresize` and `onvisible` install browser observers without custom JavaScript.
`onmounted` fires after first mount and provides a live handle for focus,
scrolling, and other element operations.

Event default prevention is synchronous since 0.6.0. Call
`event.prevent_default()` before the first `.await`; the removed
`dioxus_prevent_default` attribute is obsolete. LiveView handlers execute on
the server and need synchronous browser-side JavaScript for cancellation.

### Preview input and clipboard events

> **Prerelease (`0.8.0-alpha.1`):** This guidance may change before stable release.

Selection events and `beforeinput` are supported, allowing observation before
the browser applies an edit. Clipboard event payloads expose pasted data.

### Error propagation

An `ErrorBoundary` may be nested and uses `handle_error` to render recovery UI.
Plain component errors can propagate with `?`; async event handlers may also
return a result and use `?`. Fullstack-specific HTTP status preservation after
a boundary catches an SSR error is covered in
[fullstack-routing.md](fullstack-routing.md).
