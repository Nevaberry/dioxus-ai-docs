# Autogenerate and Rendering

## Index and constraint rendering

### Labeled index expressions (1.15.0)

Autogenerate preserves labels on index expressions. This lets PostgreSQL
operator classes keyed by a label name render against the intended expression.
Do not strip labels from generated index definitions during cleanup.

### Boolean `UniqueConstraint.deferrable` values (1.15.0)

Generated `UniqueConstraint` definitions use Python boolean representation for
`deferrable`: `deferrable=True` or `deferrable=False`. Quoted values such as
`deferrable="True"` are incorrect output from older rendering behavior.

### Final reflected names (1.16.0)

Autogenerate applies `Operations.f()` to every reflected constraint and index
name. This marks the database name as final so an active naming convention
does not transform it again, including conventions that depend on
`%(constraint_name)s`:

```python
op.drop_constraint(op.f("uq_account_name"), "account", type_="unique")
```

Preserve the wrapper when editing a generated migration.

### Named `CHECK` constraints (1.19.1)

Autogenerate detects additions and removals of named `CHECK` constraints by
default. Comparison is name-only: changing the SQL expression without changing
the constraint name does not produce a diff. Rename the constraint or author
the alteration explicitly when the expression changes.

Detection is supplied by the
`alembic.autogenerate.checkconstraint_byname` plugin. Exclude that plugin from
`EnvironmentContext.configure(autogenerate_plugins=...)` to disable the
behavior. Alembic 1.19.1 fixes erroneous detections involving column-bound
check constraints.

## Rewriters and custom writers

### Revision context on detected diffs (1.15.0)

`AutogenerateDiffsDetected` includes the revision context. Command wrappers can
use that context when translating detected differences into another output
format instead of reconstructing revision state separately.

### Renamed columns from `AlterColumnOp.modified_name` (1.15.0)

As of 1.15.2, operation rendering considers `AlterColumnOp.modified_name`.
Alembic still cannot discover column renames automatically, but a custom
`Rewriter` recipe that recognizes a rename and sets this attribute now renders
the new column name correctly.

### Configured prefix for `ExecuteSQLOp` (1.16.0)

When a custom writer embeds an `ExecuteSQLOp`, autogenerate renders
`Operations.execute()` with the namespace configured by
`alembic_module_prefix`. It no longer always hardcodes `op.`. Avoid post-process
logic that assumes generated execute calls use a fixed prefix.

## Dialect-specific comparisons and rendering

### PostgreSQL sequence defaults (1.18.0)

PostgreSQL may add a `::regclass` cast to a sequence default. Autogenerate
ignores that server-added cast when comparing defaults on non-primary-key
columns, preventing an unchanged default from recurring in every generated
migration.

### Valid `postgresql_include` values (1.18.0)

For sequence-valued dialect arguments such as `postgresql_include`,
autogenerate renders `Column` objects as string column names. Generated index
arguments should therefore be valid Python rather than object representations.

### MySQL `ENUM` comparison (1.18.0)

Autogenerate compares individual MySQL `ENUM` values. A value present on only
one side produces a diff; changing only the order of the same values does not.
Review reorder-only changes manually if ordering is significant to the
application.

## Reflection filters

### Foreign keys with excluded targets (1.18.0)

Autogenerate does not raise `NoReferencedTableError` when a foreign key target
is excluded by `include_name` or omitted from the set of reflected schemas.

An `include_object` callback that examines such a foreign key can receive a
placeholder target table. The placeholder contains the table name, schema, and
referenced columns, but it is not fully reflected. Limit callback logic to
those guaranteed fields unless full reflection has been established.
