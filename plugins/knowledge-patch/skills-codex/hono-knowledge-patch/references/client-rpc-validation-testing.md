# Client, RPC, Validation, and Testing

## Parse RPC responses by content type

Since `4.9.0`, `parseResponse()` from `hono/client` accepts an `hc` response
promise, selects its parser from `Content-Type`, and throws a structured
`DetailedError` for an unsuccessful response.

```ts
import { parseResponse } from 'hono/client'

const result = await parseResponse(client.hello.$get())
```

## Preserve precise URL and path types

Since `4.11.0`, a literal base URL supplied as the second `hc` type parameter is
preserved in the `TypedURL` returned by `$url()`. This is useful for typed cache
keys and helpers that distinguish hosts or prefixes.

```ts
const client = hc<typeof app, 'http://localhost:8787'>(
  'http://localhost:8787/'
)
const url = client.api.posts.$url()
```

Since `4.12.0`, endpoints expose `$path()`, which applies path and query
parameters but returns only a path string.

```ts
const path = client.posts[':id'].$path({
  param: { id: '42' },
  query: { view: 'full' },
})
```

The `4.13.3` `replaceUrlParam` fix keeps `$` replacement tokens literal during
path substitution. Add a regression test when client path values may contain
strings such as `$&` or `$1`.

## Keep RPC parameters in wire format

Hono Client requires `param` and `query` values to be strings even when server
validation coerces them. It interpolates path parameters without URL-encoding,
so encode ordinary values explicitly. Pass raw slashes only when the server route
deliberately accepts them through a regexp parameter such as `/:id{.+}`.

```ts
await client.posts[':id'].$get({
  param: { id: encodeURIComponent('123/456') },
  query: { page: '1' },
})
```

## Customize query serialization

Since `4.11.0`, `buildSearchParams` in the `hc` options replaces the default
query serializer, including for conventions such as bracketed array keys.

```ts
const client = hc<AppType>('http://localhost', {
  buildSearchParams(query) {
    const params = new URLSearchParams()
    for (const [key, value] of Object.entries(query)) {
      if (value === undefined) continue
      if (Array.isArray(value)) {
        value.forEach((item) => params.append(`${key}[]`, item))
      } else {
        params.set(key, value)
      }
    }
    return params
  },
})
```

## Override one RPC request deliberately

Pass fetch initialization as `{ init }` in the method call's second argument.
Those values have final precedence and can override the method, body, or headers
generated by `hc`.

```ts
await client.posts.$post(
  { json: post },
  { init: { signal: abortController.signal } }
)
```

## Compose route response types

Since `4.10.0`, route inference carries response types from middleware and
earlier handlers into `hc`. Status checks on a multi-handler route therefore
narrow all inferred response branches.

From `4.12.1`, `ApplyGlobalResponse` is exported by `hono/client` and adds
responses from global middleware or `onError()` to every route schema.
`PickResponseByStatusCode` selects one status variant from an inferred response
union.

```ts
type AppWithErrors = ApplyGlobalResponse<
  typeof app,
  { 401: { json: { error: string } }; 500: { json: { error: string } } }
>
```

For an application-specific 404 body, augment `NotFoundResponse` so
`c.notFound()` and the generated client preserve its type.

```ts
import { TypedResponse } from 'hono'

declare module 'hono' {
  interface NotFoundResponse
    extends Response,
      TypedResponse<{ error: string }, 404, 'json'> {}
}
```

## Match validator parsing preconditions

`validator('json', ...)` and `validator('form', ...)` receive `{}` when the
request lacks the matching `Content-Type`. This rule also applies to
`app.request()` tests. Header-validator input has lowercase keys, so access
`value['idempotency-key']` instead of display casing.

```ts
const res = await app.request('/posts', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Hello' }),
})
```

## Use supported schema integrations

Since `4.8.0`, `@hono/zod-validator` supports Zod 4.

For library-neutral validation, `@hono/standard-validator` exports
`sValidator()` for Standard Schema-compatible libraries such as Zod, Valibot,
and ArkType. Read the result with `c.req.valid()`.

```ts
import { sValidator } from '@hono/standard-validator'
import * as z from 'zod'

const schema = z.object({ name: z.string(), age: z.number() })
app.post('/author', sValidator('json', schema), (c) =>
  c.json(c.req.valid('json'))
)
```

## Configure generated clients and test bindings

Since `4.8.0`, `testClient` accepts `hc` options, so tests can configure the
generated client's fetch or serialization behavior.

Pass mocked runtime bindings as the third argument to
`app.request(path, init, env)`.

```ts
const res = await app.request('/posts', {}, {
  API_HOST: 'example.com',
})
```
