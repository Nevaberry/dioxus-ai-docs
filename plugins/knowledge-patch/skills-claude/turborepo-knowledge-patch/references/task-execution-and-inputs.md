# Task execution and inputs

## Write Watch Mode results to cache (since 2.4.0)

Watch Mode can write task results to the cache when explicitly enabled. The
watched task argument is required.

```bash
turbo watch dev --experimental-write-cache
```

## Run persistent sidecars (since 2.5.0)

A persistent task can use `with` to start other long-running tasks whenever it
runs. This expresses runtime coexistence instead of the completion ordering
imposed by `dependsOn`.

```json
{
  "tasks": {
    "dev": {
      "with": ["api#start"],
      "persistent": true,
      "cache": false
    }
  }
}
```

## Continue only through successful dependencies (since 2.5.0)

`--continue=dependencies-successful` continues past failures but runs a
dependent task only when all of its dependencies succeeded.

```bash
turbo run test --continue=dependencies-successful
```

## Anchor inputs at the workspace root (since 2.5.0)

The `$TURBO_ROOT$` microsyntax anchors a task input glob at the workspace root,
avoiding package-depth-dependent `../` paths.

```json
{
  "tasks": {
    "build": {
      "inputs": ["$TURBO_ROOT$/important-file.txt"]
    }
  }
}
```

## Inspect sidecar relationships (since 2.6.0)

Dry-run and summary output include `with` sidecar relationships.

## Use task-input Future Flags (since 2.9.0)

- `affectedUsingTaskInputs` makes `--affected` select individual tasks by
  their `inputs` instead of every task in a changed package.
- `watchUsingTaskInputs` makes `turbo watch` rerun only tasks whose `inputs`
  match changed files.
- `filterUsingTasks` resolves filters at task level, using `inputs` for Git
  ranges and the Task Graph for `...` traversal.

Enabling a Future Flag affects the global hash.

## Use optional profile filenames (since 2.9.0)

`--profile` and `--anon-profile` no longer require a filename. Profile output
also includes a Markdown companion beside the trace.

```bash
turbo run build --profile
turbo run build --anon-profile
```

## Shut tasks down gracefully (since 2.10.0)

On `SIGINT` or `SIGTERM`, Turborepo forwards the signal to its tasks and waits
for their cleanup handlers. Press `Ctrl+C` a second time to force an immediate
exit. No configuration is required.

## Defer task-input hashing (since 2.10.0)

Structured `inputs` objects can defer part of a task hash until upstream work
is complete. Use `mode: "jit"` for files generated by a dependency. Use
`mode: "dependencyOutputs"` to hash selected outputs of task dependencies.

```jsonc
{
  "tasks": {
    "codegen": {
      "cache": false
    },
    "build": {
      "dependsOn": ["codegen"],
      "inputs": [
        "$TURBO_DEFAULT$",
        "!src/generated/**",
        {
          "mode": "jit",
          "globs": ["src/generated/**"]
        }
      ]
    },
    "check-types": {
      "dependsOn": ["^check-types"],
      "outputs": ["dist/**"],
      "inputs": [
        "$TURBO_DEFAULT$",
        {
          "mode": "dependencyOutputs",
          "globs": ["dist/**/*.d.ts"],
          "from": ["^check-types"]
        }
      ]
    }
  }
}
```

JIT inputs are hashed after task dependencies finish. Dependency-output inputs
let downstream tasks remain cached when an upstream implementation changes but
its selected outputs, such as declarations, do not.

## Intersect affected and filtered scopes (since 2.10.0)

`--affected` and `--filter` can be combined. Only tasks or packages satisfying
both constraints are selected. Filters can also exclude packages from the
affected set.

```bash
turbo run build --affected --filter=web
turbo run build --affected --filter=!docs
turbo query ls --affected --filter=my-app
```
