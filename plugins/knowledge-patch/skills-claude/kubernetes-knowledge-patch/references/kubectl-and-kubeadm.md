# Kubectl and Kubeadm

Use this reference for kubectl preferences and output, command compatibility,
kubeadm-generated configuration, control-plane endpoints, and patch-level join
behavior.

## Kubectl preferences and output

### Keep preferences in `.kuberc` (1.33-guide, 1.34-guide)

Use `~/.kube/kuberc`, or `--kuberc PATH`, for aliases and command overrides so
they remain separate from kubeconfig credentials. The 1.33 alpha required
`KUBECTL_KUBERC=true`; normal loading is beta and enabled by default from 1.34.

```console
kubectl --kuberc /var/kube/rc get pods
```

### Restrict credential plugins (1.35-guide)

Shared preferences can set `credentialPluginPolicy` to allow or deny all
credential plugins and `credentialPluginAllowlist` to permit only named ones.

### Emit KYAML (1.34-guide, 1.35-guide)

KYAML is a less ambiguous Kubernetes-oriented YAML subset and remains valid
YAML input. Use `kubectl -o kyaml`. The alpha form required
`KUBECTL_KYAML=true`; beta KYAML is enabled by default and can be disabled with
`KUBECTL_KYAML=false`.

### Prefer the modern HPA API (1.33.0)

`kubectl autoscale` creates `autoscaling/v2` HPAs and falls back to
`autoscaling/v1` when v2 is unavailable or errors.

### Preserve null metadata keys (1.33.0)

`kubectl apply` coerces null label and annotation values to empty strings,
matching typed JSON metadata decoding instead of dropping every label or
annotation.

## Command compatibility

### Separate `kubectl exec` commands (1.35.0)

The legacy form is removed. Always put `--` before the remote command.

```console
kubectl exec <pod> -- <command>
```

### Expect the general debug profile (1.36.0)

`kubectl debug` defaults to `general`, not `legacy`. Select a profile explicitly
when automation depends on its fields; the legacy profile is planned for
removal in 1.39.

### Request events for multiple objects (1.36.0)

`kubectl describe` shows related events by default only for one exact object.
Add `--show-events` when describing multiple objects or using fuzzy prefix
matching.

### Remove legacy beta objects (1.35.0)

Kubectl no longer supports these object versions:

- `certificates/v1beta1` CertificateSigningRequest
- `discovery/v1beta1` EndpointSlice
- `networking/v1beta1` Ingress
- `policy/v1beta1` PodDisruptionBudget

## Kubelet configuration generated by kubeadm

### Use the local control-plane API endpoint (1.33.0)

Default-on beta `ControlPlaneKubeletLocalMode` makes `kubeadm init` and
control-plane `join` generate kubelet configuration for the local API server.
For `kubeadm init phase kubeconfig kubelet`, use
`--apiserver-advertise-address`; `--control-plane-endpoint` no longer selects
the generated `server`.

### Store CRI endpoints per node (1.34.0)

Default-on beta `NodeLocalCRISocket` writes the node's
`containerRuntimeEndpoint` to `/var/lib/kubelet/instance-config.yaml`. During
upgrade, kubeadm removes `kubeadm.alpha.kubernetes.io/cri-socket` from the Node
and removes `--container-runtime-endpoint` from
`/var/lib/kubelet/kubeadm-flags.env`.

### Keep probe ports synchronized (1.34.0)

Generated control-plane static Pods use the named port `probe-port`. A kubeadm
patch that changes a probe port must also change the matching container
`ports` entry.

### Clean up the sandbox-image flag (1.35.0)

Kubeadm upgrade tries to remove `--pod-infra-container-image` from
`/var/lib/kubelet/kubeadm-flags.env`, but it cannot remove user-supplied
`extraArgs`. Remove those manually because kubelet rejects the flag.

## External etcd and arguments

### Separate external-etcd HTTP endpoints (1.35.0)

Kubeadm v1beta4 `ClusterConfiguration.Etcd.ExternalEtcd` accepts
`HTTPEndpoints` for health and metrics separately from gRPC `Endpoints`.
Omitting `HTTPEndpoints` keeps using `Endpoints` for both.

### Preserve user argument order (1.36.0)

Kubeadm sorts only default component arguments and preserves user `extraArgs`
order. Ordered repeatable flags such as `--service-account-issuer` therefore
retain their precedence.

## Join and reset behavior

### Use the API-call timeout for cluster configuration (1.34.10)

`kubeadm join` fetches the `kubeadm-config` ConfigMap using the
`KubernetesAPICall` timeout, one minute by default, rather than the old 350 ms
optional-component retry. `FetchInitConfigurationFromCluster` callers may set
its new `shortConfigMapGet` parameter for the short behavior used by
`kubeadm reset`.

### Tolerate ambiguous etcd learner promotion (1.35.7)

If learner promotion succeeds server-side but the client sees a transient
error, `kubeadm join` recognizes that the member is already a voter and skips
the redundant promotion instead of retrying until timeout.
