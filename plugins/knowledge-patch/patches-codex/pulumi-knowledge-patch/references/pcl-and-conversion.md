# PCL and Conversion

## Conversion and plugin resolution

`pulumi convert --from=<plugin>@<version>` pins a converter, conversion can
bridge Terraform providers automatically, and PCL understands `try` and `can`
(batch `3.145.0-3.159.0`). Third-party conversions resolve provider plugins
through the Pulumi Registry.

The HCL runtime and converter are downloaded on demand; `pulumi convert --from
hcl` installs the converter automatically. HCL runtime support does not make
`hcl` a valid target for converting a Terraform program: that conversion is
rejected.

## Resource forms and snippets

PCL supports parameterized providers and `read` blocks, which query an existing
resource by ID without registration. Snippet blocks are retained in state to
track ad-hoc resources. Deployment options can target state snippets by UUID via
`TargetSnippets`.

PCL declares lifecycle hooks and binds `onError` hooks. It generates hooks into
Go, Node.js, and Python; a successful error-hook command retries the failed
operation. Hook calls receive resource options, and failed after-hooks fail the
deployment.

PCL component blocks apply `providers` to resources and invokes. Generated
Node.js, Go, and Python code parents component invokes so provider inheritance is
preserved (batch `3.255.0-3.258.0`).

## Types and evaluation

PCL represents secret configuration and resource ranges, and typechecks
component inputs. Labels on `package` blocks are deprecated.

Integer literals, list and tuple indices, and the `element` and `range` builtins
use integer rather than number types. Resource maps created with `range` can be
indexed by key. PCL applies resource-schema defaults, resolves invoke-derived
configuration defaults to the invoke result, and fills schema-declared nested
outputs so optional objects can be traversed safely.

Functions declared with multiple argument inputs are invoked positionally.
Project-scoped direct-resource PCL receives the selected stack organization and
short name.

## Code generation

SDK generation supports type references to parameterized and third-party
packages and supports an `OutputStyleOnly` function flag that suppresses the
plain function. Go program generation can emit provider `Call` requests.

SDK and program generation supports extension-parameterized packages; generated
tokens use the extension package's name. Provider functions with
`multiArgumentInputs` are generated by Go and Python SDK/program generators.

The .NET codegen package under `pulumi/pkg/v3/codegen/dotnet` is deprecated and
scheduled for removal. Provider tooling should use
`pulumi-dotnet/pulumi-language-dotnet/v3/codegen`.

## Import generation

Imports work with parameterized packages and providers. Program generation for
.NET, Go, Node.js, and Python emits the resource import option. Import files may
declare provider resources and associate imported resources with them.

Import generation preserves asset, archive, and resource-reference values nested
inside maps and arrays and HCL-escapes map keys containing template sequences.
Import files may include resource inputs and outputs; supplied outputs import
state directly and skip the provider read. Parameterized and
extension-parameterized providers are supported.

`ResourceImport` carries parent and properties for hierarchy and filtering.
State converters may return providers, inputs, and outputs, receive a
schema-loader and package resolver, and request mappings for a named ecosystem.
Generated import files include explicit providers. `preview --import-file` does
not emit unknowns, and `pulumi import` rejects input files that contain unknowns.

## Schema and PCL binding

PCL/schema binding requires an explicit schema loader. Schema defaults are
applied during evaluation. Resource references sent on the wire include `Name`
and `Type`, and provider references on `Call` use `__self__`.
