# Code Generation and Builtins

Use this reference for optimizer behavior, low-level assembly, allocation contracts, compiler attributes, and builtin availability.

## Optimizer and code-generation controls

### Static destructors and debug liveness

Clang 20 (`clang-20.1`) adds `-fc++-static-destructors={all,thread-local,none}`. `all` is the default; `none` is equivalent to `-fno-c++-static-destructors`. `-fextend-variable-liveness[=all]` preserves user variables and `this` for optimized debugging, while `=this` limits preservation to the C++ implicit object.

Clang 21 (`clang-21.1`) makes `-Og` enable `-fextend-variable-liveness`. It adds DWARF-only `-gkey-instructions`, continuous profiling with `-fprofile-continuous`, `-ignore-pch`, and `-fthinlto-distributor=`/`-Xthinlto-distributor=` for externally distributed ThinLTO backends. On Windows, `-static-libclosure` only alters Blocks-extension code generation; it does not change linker behavior by itself.

Clang 22 (`clang-22.1`) enables `-gkey-instructions` by default for optimized plain C or C++ with DWARF. `-fconstexpr-steps=0` removes the constant-evaluation step limit, `-fdevirtualize-speculatively` enables otherwise-disabled speculative virtual-call devirtualization, and `-fmatrix-memory-layout={column-major,row-major}` selects Clang matrix storage order.

### Floating-point model

In Clang 20 (`clang-20.1`), `-ffp-model=fast` no longer assumes finite-only arithmetic and uses promoted complex division where possible. `-ffp-model=aggressive` selects the former, more aggressive `fast` behavior.

### Incremental LTO

GCC 15 (`gcc-15.1`) adds incremental link-time optimization through `-flto-incremental=`.

### Global allocation assumptions

GCC 15 (`gcc-15.1`) enables `-fassume-sane-operators-new-delete` by default. A program whose replacement global allocation functions expose global state may require `-fno-assume-sane-operators-new-delete`.

## Assembly and low-level control

### Extended assembly

GCC 15 (`gcc-15.1`) permits restricted extended assembly outside functions. Assembly that overwrites the stack red zone can declare the special `"redzone"` clobber. C++ assembly strings can also be generated by constexpr evaluation.

Clang 21 (`clang-21.1`) accepts GNU `asm` strings as constant expressions, for example:

```cpp
asm((std::string_view("nop")) ::: (std::string_view("memory")));
```

With branch-target enforcement in Clang 21, `asm goto` labels are not guaranteed to begin with `bti` or `endbr64`; register-controlled branches must not target them.

Clang 21 (`clang-21.1`) also implements P2719R5 type-aware allocation and deallocation as an extension in every C++ language mode.

### Noncapturing GNU C nested functions

GCC 16 (`gcc-16.1`) guarantees that a nested function which does not capture its environment needs no run-time trampoline. This matters for code that forbids executable-stack-style trampoline support.

## Contracts and source annotations

### Tail calls and pointer/count relationships

GCC 15 (`gcc-15.1`) adds a `musttail` statement attribute to require a tail call. The `nonnull_if_nonzero` function attribute says a pointer parameter must be non-null when a separate size or count parameter is nonzero.

Clang 20 (`clang-20.1`) adds `__builtin_counted_by_ref(flexible_member)`, which returns access to the counter named by a flexible member's `counted_by` attribute. Allocation helpers can initialize the count before sanitizer-checked access:

```c
*__builtin_counted_by_ref(p->items) = count;
```

GCC 16 (`gcc-16.1`) extends `counted_by` to pointer members:

```c
struct buffer {
  unsigned count;
  int *data __attribute__((counted_by(count)));
};
```

### Clang source annotations

Clang 20 (`clang-20.1`) adds `[[clang::no_specializations]]`, `[[clang::lifetime_capture_by(X)]]`, `[[clang::coro_await_elidable]]`, `[[clang::coro_await_elidable_argument]]`, and `__attribute__((format(syslog, ...)))`. `swift_attr` can annotate types.

Clang 21 (`clang-21.1`) adds `__attribute__((format_matches(...)))` for format-forwarding wrappers. X86-64 globals can select `model("small")` or `model("large")` independently of the translation unit. `[[clang::atomic(...)]]` controls AMDGPU atomic metadata per statement. Attributes before an `extern template` declaration are rejected.

Clang 22 (`clang-22.1`) adds `malloc_span` for functions returning pointer-and-size or pointer-pair structures and `modular_format` for static-libc `printf` feature selection at link time. On Itanium targets, `[[gnu::gcc_struct]]` requests Itanium record layout even when Microsoft bit-field layout is active. `[[clang::cfi_unchecked_callee]]` propagates from declaration to definition and suppresses `-fsanitize=function` on affected indirect calls.

### GCC attribute behavior

GCC 15 (`gcc-15.1`) accepts C++11 attributes in C++98 mode. `flag_enum` can suppress inappropriate switch warnings, and `-Wdefaulted-function-deleted` diagnoses explicitly defaulted functions that become deleted.

## General-purpose builtins

### Clang 20 elementwise and type builtins

Clang 20 (`clang-20.1`) adds:

- `__builtin_elementwise_popcount`;
- `__builtin_elementwise_fmod`;
- `__builtin_elementwise_minimum` and `__builtin_elementwise_maximum`;
- `__builtin_elementwise_atan2`;
- `__builtin_common_type`.

Integer reduction and elementwise bit/count/saturating builtins, floating-comparison builtins, `__builtin_signbit`, and `__builtin_abs` become usable in constant expressions.

### Clang 21 invocation and vtable builtins

Clang 21 (`clang-21.1`) adds `__builtin_elementwise_exp10`, `__builtin_elementwise_minnum`, `__builtin_elementwise_maxnum`, `__builtin_invoke`, and `__builtin_get_vtable_pointer`. `__builtin___clear_cache` now has signature `void(void *, void *)`, matching GCC rather than taking `char *`.

### Clang 22 template and comparison builtins

Clang 22 (`clang-22.1`) adds `__builtin_{lt,gt,le,ge}_synthesizes_from_spaceship` to report whether a relational operator comes from `<=>`. In template arguments or base specifiers, `__builtin_dedup_pack<Ts...>...` produces an unexpanded pack with duplicate types removed.

### Clang 22 vector and memory builtins

Clang 22 (`clang-22.1`) adds `__builtin_elementwise_ldexp`, `__builtin_elementwise_fshl`/`fshr`, `__builtin_elementwise_minnumnum`/`maxnumnum`, generic `__builtin_bswapg`, `__builtin_stack_address()`, and masked load/store/gather/scatter builtins.

Integer elementwise min/max and abs become constant-expression capable. Fixed boolean vectors work with generic popcount/count-zero builtins and as `?:` conditions. `__builtin_assume_dereferenceable` accepts run-time sizes.

## Target-specific builtin constraints

Clang 20 (`clang-20.1`) makes `*mmintrin.h` intrinsics operating on `__m64` use SSE2 and XMM registers. They no longer work on MMX-only targets or with `-mmmx -mno-sse2`; MMX inline assembly remains supported. The former direct `__builtin_ia32_*` implementation builtins are removed, so call the header intrinsics instead.

During offloading, Clang 22 (`clang-22.1`) evaluates `__has_builtin` only for the currently active target. Do not use a host builtin probe as evidence for the device compilation.
